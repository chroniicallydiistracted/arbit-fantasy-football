# Comprehensive nflverse foundation implementation plan

> **For agentic workers:** Use executing-plans inline with test-driven development; one fresh final whole-branch reviewer.

**Goal:** Import the full published nflverse data surface, historical and current, into reproducible local storage, with verified manifests, honest coverage and canonical player joins.

**Architecture:** Enumerate all official nflverse-data release groups and the ffverse sources exposed by nflreadr. Select one complete representation per logical file (Parquet preferred, CSV/RDS fallback), preserve all columns and variants, and retain metadata/legacy/diagnostic distinctions. Stream immutable source objects, validate/normalize into immutable Parquet, and atomically publish versioned PostgreSQL manifests/current pointers. Exact trusted GSIS/ESPN crosswalks reuse FFA identities; ambiguity stays in a review queue.

**Tech stack:** Existing Python/PostgreSQL/worker/API; add PyArrow for bounded columnar processing and pyreadr for source-only RDS tables. No R runtime, source code execution, hosted service, member auth, model or recommendation enablement.

**Spec:** Approved data architecture/ADR002 and requirements DATA-002/005, MD-004 prerequisites. Owner explicitly requested all-encompassing nflverse inclusion on2026-10-31; broad catalog/import scope is authorized. Existing architecture approval continues; no repeated design gate.

## Global constraints

- ESPN remains authoritative FFA truth; nflverse is statistical foundation. Keep all original fields/missingness; no source fantasy-point columns substituted for FFA scoring.
- Include every discovered core release/logical file and official loader family, not a handpicked sample. Record unsupported/diagnostic/metadata assets explicitly; ffverse rankings/opportunity are benchmark/reference only. Model ZIP artifacts are cataloged separately, never executed or represented as football observations.
- Full historical seasons by published assets, configured2026 coverage explicit. Prefer Parquet over format mirrors without dropping statistical subtypes, season-summary scopes or legacy variants. Initial inventory:25release groups, roughly1000logical files/1.1GB before ffverse;870GB local free, no paid resources.
- Preserve original bytes/checksums and immutable normalized versions, schema/coverage/terms/observation metadata. A timestamp in a current download does not establish historic publication availability. Conservative as-of selection uses first local observation; event time and provider asset update time are separate.
- Public fixed-origin GETs only, bounded bytes/redirects/retries, no environment credentials/cookies/proxies. Reuse durable queue/fencing and shared provider gate; nflverse traffic must not block ESPN's independent budget.
- Native GSIS and exact trusted crosswalks only. Never name-only merge, backdate identity evidence or overwrite conflicting aliases. NFL teams and D/ST remain separate. Unknown joins are visible.
- New additive0003migration; leave prior migrations intact. Local commands guard non-production/loopback databases. Default API/member access policy unchanged; new local read endpoints reuse the optional operator boundary. No pushes, merge or deployment.

## Review focus

- Mutable release assets changing between discovery/download; checksum/length mismatch or metadata refresh must not promote partial data.
- CSV/RDS inference losing leading-zero IDs, changing missing values, stripping columns or exploding memory; preserve source semantics and fail unsupported inputs safely.
- Partial historical coverage, annual vs weekly vs timestamped depth data and post-season-only participation; do not infer availability or feature readiness from a filename.
- Conflicting/missing crosswalk IDs and prior UUIDs; keep last trusted mapping and source evidence, no silent entity merges.
- Retry/restart, late worker completion, concurrent import/current-pointer ordering, corrupt immutable files and as-of leakage; old or failed inputs cannot replace valid current data or fabricate past knowledge.
