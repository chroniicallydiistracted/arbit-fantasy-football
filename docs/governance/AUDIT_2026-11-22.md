## Test/evidence classification

- **Observed in audit environment:** original foundation validator passed; governance CLI structural and unit tests passed; metadata/file checks passed.
- **Not available here:** full workspace frozen runtime validation, PostgreSQL-backed integration, actual OIDC/member flows, browser rendering, live NFL/ESPN provider freshness, or production deployment. Local Python is 3.13 and Node is 22, whereas the repo pins Python 3.12.13 and Node 24.22.2; `pyarrow`, `psycopg`, and pinned pnpm workspace dependencies were not present in the audit environment.
- **After application:** install frozen dependencies in the owner's isolated development environment, run `make runtime-check` and `make web-check` where relevant, protect `main` with required CI/check reviews, then have a fresh Codex and Claude session independently run `brief`/`doctor` and describe the same open task without chat context.

## Remaining risks

1. File-based and CI evidence checks do not prove human approval, semantic correctness, provider validity or truth of a handwritten journal statement.
2. GitHub Actions cannot be proven operational without pushing to the user's repository. The PR diff gate enforces traceability only if the workflow is required by branch protection and its configuration is reviewed.
3. The task recorder supports one active task per checkout; coordinated parallel contributors should use separate worktrees and explicit file ownership, then integrate under one reviewed task.
4. Deletions require explicit `--deletions` scope and GitHub PR coverage; manual reviewer approval remains necessary. The gate verifies declared deletion and corresponding checks, but cannot infer whether deletion was desirable.
